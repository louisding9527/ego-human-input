# ego-lite 拟人化输入与站点频率控制 skill

## 1. Goal

产出一个可加载的 skill。AI 加载后，在调用 ego-lite 执行网页操作时，鼠标、键盘、停顿、频率四类行为都按站点参数拟人化。目标是让自动化行为在站点风控视角下不表现为规律机器节奏。

用户价值：同一份业务脚本不改业务逻辑，换站点时只换一套参数。

## 2. 背景与已确认事实

以下事实在本机实测或读文档确认，均可作为设计依据。

**ego-lite 能力边界**

- 已装版本 2.2.0（`ego-browser skill` 输出末行为 `[ego-browser:skill] end of guide v2.2.0`）。
- 原生输入原语：
  - `page.mouse.move(x, y, { steps?, label? })`
  - `page.mouse.click(x, y, { button?, clickCount?, delay?, label? })`
  - `page.mouse.down() / up() / wheel(dx, dy, { label? })`
  - `page.keyboard.type(text, { delay? }) / down / up / press / insertText / paste`
  - `page.waitForTimeout(ms)`
  - `page.cdp(method, params)` / `task.cdp(...)`
- 无内建拟人逻辑，无限速器，无 stealth 开关。
- 指南禁止 import Playwright、禁止另起浏览器。ghost-cursor 一类 Playwright 生态库不可用，轨迹算法只能自写。
- Page 会话默认对 CDP 隐藏 console，站点看不到。`egoAutomated.disable` 会关闭这项保护，不得使用。
- 脚本每轮是独立进程，不继承 shell 工作目录与环境变量。本地模块只能用绝对路径动态 import：`await import('file:///D:/.../human.mjs')`。
- 脚本无文档化的单轮总时长上限；`page.evaluate()` 有安全超时。5~8 秒停顿能否稳定放进单轮脚本，需在实现阶段实测。

**坐标与选择器**

- `page.snapshot({ includeStableLocator: true })` 输出形如 `anchor [ref=1, loc=href:https://iana.org/help/example-domains]`，有稳定 locator，但**不含坐标**。
- `page.click(selector, { position, delay })` 接受相对元素左上角的偏移，不接受绝对坐标。
- 结论：拟人轨迹需要目标坐标，必须先自行求元素 rect（`page.evaluate` 或 CDP `DOM.getBoxModel`）。ref 到坐标的换算链路目前缺失，是设计要解决的点。

**行为检测的优先级判断**

成熟风控（Cloudflare、DataDome、Akamai）主要按 IP 信誉与浏览器指纹评分，不按鼠标轨迹。轨迹与击键拟人的实际收益在于通过 JS 层行为检测、避免"过于规整"。这条判断决定参数不能无限加码：过度随机化本身也是特征。

**ego-lite 的指纹与登录态现状（2026-11-10 实测）**

本机只有 1 个 profile（默认，名 `吕航 丁`），ego 用真 Chromium 156 跑在真实机器上。在 `example.com` 实测页面可读值：

| 项 | 实测值 | 含义 |
| --- | --- | --- |
| `navigator.webdriver` | `false` | Playwright 默认会置 `true`，ego 没有 |
| `userAgent` | Chrome/156.0.0.0，无 Headless 标记 | 真浏览器 |
| `WebGL renderer` | `ANGLE (Intel, Intel Arc 130T, D3D11)` | 真实 GPU 型号，无像素级伪造 |
| 时区 / 硬件 | `Asia/Shanghai`，14 核，32GB | 真机 |
| plugins / mimeTypes | 5 / 2 | 正常 Chrome 填充 |
| `chrome.runtime` | `undefined` | 普通页面本就没有，不是缺陷 |
| CDP 泄漏对象 | 无 | 无 `cdp` / `playwright` / `puppeteer` 痕迹 |

结论：指纹层不需要本 skill 做任何事。真机真浏览器真 GPU 天然一致，改任何一项反而制造内部矛盾（例如改 UA 与 WebGL、字体、时区不一致）。**这条改写"防反爬"的重心：真正要保护的资产是用户真实的登录态，不是匿名身份。**

登录态被风控标记的代价，远高于匿名爬虫被封 IP。因此速率必须保守，理由是保护账号，不是躲检测。

## 3. Requirements

### R1 站点识别与频率档案

脚本在操作前识别当前站点，输出一份生效参数。参数至少覆盖：每分钟动作数、动作间隔区间、页面停留区间、滚轮次数区间、键盘组间间隔。

**已定方案（2026-11-10）**：本地站点档案表 + 域名匹配 + 未知站通用保守档 + 运行时探测降档。

- 档案表是随 skill 分发的 JSON，按域名（含子域）匹配，命中用精调参数。
- 未命中时不报错，落到通用保守档：频率取低值、停顿取高值。
- 运行时探测作为二级修正：页面或响应出现 CDN / 风控特征（如 `cf-ray`、挑战页标记）时，在命中的档案上再降速一档。探测只降不升，避免误判把节奏调激进。
- 档案可本地覆盖：用户目录下的同结构 JSON 与内置表合并，本地项优先，便于不重装 skill 就能调参。

**首批站点（2026-11-10 定）**：猎聘 `liepin.com`、BOSS 直聘 `zhipin.com`、前程无忧 `51job.com`、智联招聘 `zhaopin.com`、脉脉 `maimai.cn`、LinkedIn `linkedin.com`。

**首版深度（2026-11-10 定）**：统一模板。

- 基线不由测试定。能不能量化"不被封"没有可测口径，测试只能证明机制生效（事件数量、时间差、isTrusted），不能证明参数最优。
- 因此首版给六站各一条档案，全部继承同一模板默认值，档案里只保留可覆盖字段。用户后续按实际遇到的情况自己调。
- 结论：不做首版精调，也不设计调参流程。档案结构要让人直接改 JSON 就能生效。

六站都是招聘/职场类站点，动作集合按同一套假设建模：浏览列表、翻页、进详情、搜索筛选、填表、投递或发消息。停顿与滚轮的出现位置按动作类型绑定，不按站点硬编码。若某站有独占动作（如 BOSS 的聊天），在实现阶段补一条专属规则即可。

### R2 拟人维度参数化

输入拟人拆成独立维度，每个维度有自己的参数与开关。维度清单：

| 维度 | 参数 |
| --- | --- |
| 鼠标移动 | 轨迹类型、控制点数、采样点数、每步间隔、落点抖动 |
| 鼠标点击 | 按下时长、点击前悬停、连击间隔 |
| 键盘（拉丁字符） | 单键间隔、词内间隔、组间间隔、误输入概率 |
| 键盘（中日韩） | 词组分段、组间停顿、整段插入方式 |
| 滚轮 | 单次 delta、滚动步数、步间间隔 |
| 停顿 | 时长区间、出现概率、与滚轮的组合方式 |
| 动作速率 | 每分钟上限、连续同类型动作的衰减 |

每个维度可单独关闭，便于排查"到底哪一层在起作用"。

### R3 鼠标轨迹

从 A 点到 B 点必须是多点连续路径，不是一次跳变。参数化以下选项：

- 轨迹族：贝塞尔（三次，控制点带随机偏移）、最小抖动（沿直线加垂直噪声）、过冲回拉（先越过目标再回修）。三种随机选用。
- 采样：12~26 个中间点，每点之间真实 `await sleep()`，不是 `steps` 参数内部的瞬时插值。
- 速度曲线：中段快、两端慢（ease-in-out），符合人手加减速。
- 落点：先落到目标附近 ±3px，停顿后再校正到目标点。

必须说明的取舍：`mouse.move` 的 `steps` 只做一次 CDP 调用内的插值，事件时间戳几乎相同，拟人价值为零。只能循环调用多个 `move` 并在中间真实等待。

### R4 键盘节奏

- 拉丁字符：逐键 `keyboard.type(ch)`，词内间隔可快，词间停顿拉长。
- 每输入两组后插入一次故意误输入：打错一个字符，停顿，按退格，再继续。概率可配，默认开启。
- 中文场景是硬约束：中文没有逐键按键事件，`keyboard.type` 对中文只能整段合成。真实中文输入走输入法候选，无法复现。因此中文按词组切分后 `insertText`，词组之间加 0.3~1.2s 停顿，误输入改为"整段删掉重打"或不启用。
- `keyboard.paste()` 是瞬时行为，与拟人目标冲突，业务允许时也要限用。

### R5 浏览停顿与滚轮

- 页面停留 5~8 秒，其间插入 1~2 次滚轮。
- 停顿与滚轮是组合，不是二选一：进入停顿 → 等 0.5~1.5s → 滚 1~2 段 → 再等剩余时间。
- 滚轮要分段：每次 `wheel` 的 delta 随机在 120~400 之间，2~5 段，段间 80~300ms。不能一次滚 600 像素。
- 需要实测 ego-lite 单轮脚本能否容纳多次 5~8 秒停顿而不被框架超时打断。

### R6 例外与边界（用户提出的第 6 点）

- 目标在视口外：先滚到可见再算坐标，否则轨迹起点错误。
- iframe 与 shadow DOM：坐标是相对顶层文档还是 iframe，需按 ego 的 frame 规则换算。
- 页面弹窗、`receipt.dialog`、权限提示会打断轨迹；出现时中止拟人序列，人工或显式处理。
- 拟人中途页面跳转：旧坐标失效，必须重新求 rect，不能复用。
- `task.handOff()` 之后不得继续拟人动作。
- 验证码或风控页出现：停机并上报，不做重试绕行。
- 同一 TaskSpace 多标签页：鼠标位置是全局共享的，轨迹起始点必须全局记录，不能按页各自记。
- 频率状态跨轮：每轮是独立进程，限速器状态需要落盘，否则多轮连续操作会叠加超速。
- 反向风险：过度随机、参数过多导致行为分布不自然。默认档要保守，可观测优先。

### R7 挑战页交接（替代"抛错停机"）

检测到挑战页或验证码时，不抛错让业务脚本崩，而是：

1. 立即停止当前拟人序列，不继续点击。
2. 记录现场（URL、检测到的特征、已执行动作数）到时间线。
3. 调 `task.handOff()` 交还用户，输出「哪一页、什么特征、需要你做什么」。
4. 用户处理完回来说继续，再从同一 TaskSpace 恢复。

理由：ego-lite 的定位是人机共用一个浏览器。遇挑战时交给人是最符合它设计意图的处理，也避免脚本反复触发风控。

### R8 开工体检（每轮开头一次）

`human.create()` 内做一次轻量检查，输出 `{ profile, webdriver, ua, gpu, tz }`：

- `webdriver === true`：说明连接方式不对，告警并要求确认。
- UA 含 Headless 标记：告警。
- 时区与用户所在时区不符：记录，不改。
- profile 名与预期不符：告警，避免在错误登录态下操作。

目的：复用登录态意味着 profile 质量直接决定成败，连错 profile 比被检测更常见。

## 4. Acceptance Criteria

- [ ] A1 给定 URL，脚本单次调用输出识别的站点档案名与生效参数 JSON，未知站点落到通用档且不报错。
- [ ] A2 一次 A→B 移动产生 ≥8 个 `mousemove` 事件，相邻事件时间差 ≥4ms 且不全等，路径偏离直线。
- [ ] A3 拉丁文本输入时，键间隔落在配置区间内；中文按词组 `insertText`，组间间隔 300~1200ms。
- [ ] A4 每两组输入后出现一次"误输入 + 退格"序列，开关可关闭。
- [ ] A5 一次浏览停顿产生 5~8s 静默，其间含 1~2 次滚轮，滚轮 delta 非固定值。
- [ ] A6 页面内自测：所有鼠标与键盘事件 `isTrusted === true`。
- [ ] A7 不得调用 `egoAutomated.disable`。
- [ ] A8 单个维度可单独关闭；关闭后该维度退化为原始 ego 行为，其余维度不受影响。
- [ ] A9 完整示例脚本可在真实站点跑通一次"进入页面 → 停顿 → 滚轮 → 输入 → 提交"，并留下可复核的时间线日志。
- [ ] A10 模拟挑战页时，脚本不停机崩溃，而是 handOff 并输出可读的现场说明；用户处理后可恢复。
- [ ] A11 `human.create()` 输出体检结果；`webdriver=true` 或 UA 含 Headless 时给出告警而不是静默通过。

## 5. Out of Scope

逐项核对 ego-lite 现状后的结论。分三类：已被 ego-lite 天然满足、值得收到范围内、确认不做。

| 项 | ego-lite 现状 | 结论 |
| --- | --- | --- |
| 浏览器指纹伪造 | 实测 `webdriver=false`、真 UA、真 GPU、真时区，无 CDP 泄漏 | **不需要做**。真机天然一致，伪造反而制造矛盾 |
| TLS / JA3 伪装 | 真 Chromium 网络栈，本机直连 | **不需要做**，skill 层也碰不到 |
| 代理 / IP 轮换 | 走用户本机网络，IP 即真实 IP，信誉正常；CLI 无 proxy 参数 | **单账号场景不需要**。批量多账号才需要，属越界 |
| 账号池 | 有 `profiles()` / `profileId`，技术上可切多个登录态 | **不做**。与"复用真实登录态"前提直接冲突，风险最高 |
| 验证码 / 封禁页绕过 | 有 `task.handOff()` 可交还用户 | 自动绕过**不做**；但"检测到挑战 → 自动 handOff"要做，见 R7 |
| Playwright 生态库 | 指南明令禁止 | **不做** |
| 业务抓取逻辑 | — | **不做** |
| 站点侧对抗升级 | — | **不做**，只保留档案可调 |

从这张表里收回范围内的三项，已并入 R7 与 R8。

# ego-human-input

给 [ego-browser（ego-lite）](https://github.com/CitroLabs/ego-lite) 补上「一双手」：
让 agent 的点击、输入、滚动落在人类行为的分布里，而不是靠限速器祈祷。

它是一层输入库，装成 skill 由 AI 加载，也能被业务脚本直接 `import`。

```js
const { human } = await import("file:///<SKILL_DIR>/lib/human.mjs");
const h = await human.create(page);
await h.run("search", { kw: "供应链总监" });   // 一次意图，内部执行整条配方
await h.flush();
```

---

## 一、这是什么

ego-lite 给 agent 一双眼睛：真实 Chromium、真实登录态、页面可读可看。
但「看见」不等于「动手」。agent 一旦开始操作页面，就立刻暴露在站点的行为风控下。

这一层管的是动手：

- 动作必须由指针或按键产生，不由脚本产生；
- 轨迹、节奏、停顿按分布采样，不按固定值；
- 序列不重复，读与写保持比例；
- 越界就停手、留证据，不硬撑。

三个约束决定了它的形态：

1. **不启动独立进程。** 它就是一组 ESM 模块，跑在 `ego-browser nodejs` 里，和业务脚本同一个进程。
2. **不接管页面。** 业务脚本仍持有 `page`，但写路径只能经 `h.*`；读路径经 `h.inspect.*`。
3. **站点知识不在代码里。** 档案、经验、配方都落 SQLite，换站不改库。

---

## 二、站点在判什么

反爬不是一个东西，是几类信号。搞清它们在判什么，才能谈怎么设计。

| 维度 | 站点看到的现象 | 自动化痕迹 |
| --- | --- | --- |
| 动作出处 | `isTrusted=false`；只有 `click`，没有 `pointerdown → mousedown → mouseup` | 脚本直接调 DOM |
| 轨迹 | 一次 `mousemove` 从 A 跳到 B，中间没有采样点 | 指针瞬移 |
| 节奏 | 间隔恒定、近似均匀分布 | 定时器节奏 |
| 序列 | 同一组动作反复出现；只搜索、从不打开详情 | 固定流程 |
| 会话 | 落地立刻操作；连续作业数小时；没有阅读 | 机器作息 |

这些信号有一个共同点：**它们都不是「总速率」**。
所以限速器能通过，站点照样拦——这一点在第三节的数据里能看到。

---

## 三、一条主张

> 目标不是「慢一点」，是「落进人类行为的分布」。

这条主张是被三次真实拦截纠正出来的。当时已经有限速器（18 次/分钟、最小间隔 0.8–2.4 秒），
三次拦截里它的占用率分别是 **5%、18%、18%**，一次都没触发。

| 现象 | 动作量 | 结果 |
| --- | --- | --- |
| 40 分钟内 12 轮「搜索 → 开详情 → 收藏 → 回列表」 | 约 39 次 | 图形验证码 |
| 2 分钟内同一按钮反复点（保存没生效） | 集中 6 次无效点击 | 图形验证码 |
| 3 分钟 5 轮「进搜索页 → 改词 → 提交」 | 10 次，0 次开详情 | 定时封禁 2 小时 |

结论：站点拦的是**结构重复**，不是总量。于是设计目标从「限速」改成三件事：

1. 动作由指针和按键产生，事件来源与人工一致；
2. 「同一序列反复出现」在触发阈值前被自己拦住；
3. 出问题时立刻停、留证据、可复盘。

## 四、怎么做到

五个手段，对应第二节的五个维度。

**1. 约束内采样，越界即失败。**
写动作只能由指针或按键发起。`tools/lint-script.mjs` 静态拦住 DOM `click()`、`dispatchEvent`、
直接写 `value`、`page.fetch`、`scrollIntoView`。页面内驻留哨兵，统计 `isTrusted=false` 的输入事件；
哨兵只装 `addEventListener` 与 `MutationObserver`，不挂全局对象、不改原型、不包 `fetch`，
状态只能通过一次随机名事件读回——自审机制本身不能成为新的痕迹。
拿不到坐标直接抛 `s1-missing`，**不降级成原生跳变点击**——静默降级会让拟人形同虚设。

**2. 四道闸门。**
会话形状（首动作前停留、单次作业时长、日总量、休息间隔、读写配比）、预警状态
（`warn` / `escalated` / `halted`）、小时配额（按 站点 + 动作类型）、同类最小间隔 + 全局令牌桶。
配额是预留-确认两段式：定位失败、元素不可点这类没发生交互的失败会把配额还回去。
配额与冷却写 `host_state`，**跨进程生效**：被封后下一个脚本起来直接 `halted`，不会一上班就补刀。

**3. 事后校验。**
每次动作后检查：URL 分类（挑战域 / 挑战路径 / 域漂移 / 登录页）、挑战页 DOM 特征、软提示 toast、
哨兵里的 `untrusted` 计数、以及 300ms 内 URL 与 DOM 都没动的「无响应点击」。
同目标 30 分钟内第二次无响应 → 熔断。

熔断与挑战页都是**停手**，停手必须有人接手才成立，否则只是静默挂起。所以冻结的那一刻会发一条
浏览器通知，说清「在哪个站点、为什么停、你该做什么」；业务脚本再用 `onBlock` 把 space 交给用户。
通知只需要一次授权（站点允许通知 + 系统允许 Chrome 通知），不装 app、不需要 token；
引导命令 `node tools/notify-setup.mjs <站点>` 会弹出授权气泡，点完 `--check` 验证。
没授权时降级为一条 `notify {ok:false}` 记录，**不会假装通知到了**。

**4. 站点知识进数据。**
`site_notes` 按 `platform + intent + kind` 归档：平台、意图、经验类型。
经验分 `site` 与 `global` 两层：只有 `hint` / `timing` 且不含 selector 的经验才能跨站晋升。

**5. 意图封装成配方。**
原子直调的问题不是原子性，是**每一步都要一次模型往返**。7 步的流程，光「想下一步」就要 3–5 分钟。
配方把走通的序列固化，agent 只发意图：同一条流程实测 **95.7 秒**，一次调用。

配方里的每一步仍走同一套原子动作与闸门，安全性不因封装而降低。

## 五、怎么证明有效

「像人」必须能被判定，否则只是一个形容词。判定分三层。

| 层 | 做法 | 是否承诺 |
| --- | --- | --- |
| L1 构造断言 | 对已记录的 run 检查 11 条：非信任事件为 0、无降级、落点不扎堆中心、落点中位偏移、移动采样点下限、步长间隔 CV、按键间隔 CV、读写比下限、首动作前停留、会话时长上限、当日动作总量 | 承诺 |
| L2 离线重放 | 拿两份 run 的分项逐条对照，任一项退化超过 5% 判退化 | 承诺 |
| L3 在线结果 | 意图成功率、单意图耗时、结果数、详情页数、拦截事件 | 只作参考 |

**为什么 L3 不算承诺**：真站拦截率受账号、时段、站点策略影响，不可控。
把它写进承诺，等于把不可控的东西当保证。

**为什么必须双指标。** 风险分单独下降没有意义。只优化风险，agent 会学出
「少做动作、少开详情、永不报错」的策略——分数很好看，实际什么都没干。
所以每次判定同时看风险与产出。

```bash
node tools/verify-human.mjs                    # 判定最近一次 run
node tools/verify-human.mjs --run <id> --json  # 指定 run，机器可读
node tools/verify-human.mjs --baseline <id>    # 与基线对照，检查退化
node tools/verify-human.mjs --db <path>        # 指向另一份库
```

判定失败退出码为 1，可直接接入 CI。阈值冻结在 [profiles/thresholds.json](profiles/thresholds.json)，
**只读**；运行时档案覆盖不影响判定。

### 当前达标情况

以下是真实跑出来的结果，不是目标值。**标注「合成回放」的项用的是造出来的事件流，不是真站**——
机制验证通过，真站尚未复测。这个区别必须写清，否则等于把机制验证冒充效果验证。

| 断言 | 现状 | 说明 |
| --- | --- | --- |
| 非信任输入为 0 | 达标 | 历史 run 实测 0 |
| 无降级动作 | 达标 | 拿不到坐标即抛错 |
| 落点不扎堆中心 | 达标（真站 1 次） | 3 次点击偏移 9.3 / 5.4 / 5.8px，居中率 0% |
| 落点中位偏移 ≥ 3px | 达标（真站 1 次） | 真站中位 5.8px；元素太小（< 10px）时回退中心，并如实记为 0 |
| 移动采样点 ≥ 10 | 达标 | 一次移动 20–63 个 `mousemove`，相邻最小间隔 12ms |
| 步长间隔 CV ≥ 0.15 | 达标（真站 1 次） | 真站 CV 0.241，步长 6–14ms 不等距 |
| 按键间隔 CV ≥ 0.15 | 达标（真站 1 次） | 真站 CV 0.232，3 次上屏间隔 898 / 518 / 636ms |
| 读写比 ≥ 25% | 达标 | 历史 run 实测 66.7%；现在低于下限会在写动作前自动补一次短阅读 |
| 首动作前停留 ≥ 300ms | 达标（真站 1 次） | 真站 4633ms（dwell + 首屏阅读） |
| 会话时长 ≤ 120min / 当日 ≤ 400 | 达标（真站 1 次） | 真站 4min / 109 个动作；超限抛 `session-long` / `daily-quota` |

对 v0.6 之前的历史 run 直接跑门禁会大面积 FAIL，因为老数据没有落点与间隔序列。
这恰好说明一件事：**门禁只对带观测的 run 有效**，之前的数据无法追认。

上一版列出的六处缺口（会话形状、配额扣除时机、哨兵暴露面、时间分布、观测粒度、四处小不一致）
已在 v0.7 补完，并在 h.liepin.com 上真站复测一次（11/11，细节见 [validation.md](validation.md)）。
剩下的两件事写在 [docs/architecture.md](docs/architecture.md)：阈值仍是没有真人样本校准的工程值，
以及**一次复测不等于统计结论**，跨站点、跨意图还要多跑。

单测 81 条：`node --test "tests/*.test.mjs"`。

## 六、演进

按能力阶梯看，不按时间线看。每一级解决一个具体问题，并留下可复跑的验收。

| 级 | 版本 | 解决什么 | 怎么验证 | 还缺什么 |
| --- | --- | --- | --- | --- |
| 1 | v0.1 | 动作像人：轨迹、键盘节奏、阅读停顿 | 一次移动 20–63 个采样点，间隔 10 种以上，`isTrusted` 全真 | 动作仍能被脚本触发 |
| 2 | v0.2 | 动作是人发的：禁写不禁读、lint、哨兵、四态预警 | 六条反例全被拦；挑战页注入后抛 `HumanBlocked`；跨进程冷却生效 | 序列还是会重复 |
| 3 | v0.3 | 序列像人：原子动作 + 经验表 | 猎聘搜索链路跑通，误报修复后 `alerts=0` | 每步一次往返，慢 |
| 4 | v0.4 | 意图封装：配方 | 7 步 95.7 秒，一次调用；原子直调同流程 3–5 分钟 | 配方得靠实测攒 |
| 5 | v0.5 | 站点知识：经验按 平台 + 意图 + 类型 归档 | 同意图去重只加 `hits`；配方失败自动落坑 | 经验不能跨站复用 |
| 6 | v0.6 | 可判定：观测字段、冻结阈值、门禁、经验分层、迭代台账 | 37 条单测；合成回放样例门禁 6/6 | 会话形状、分布形状、哨兵暴露面 |
| 7 | **v0.7（当前）** | 会话与分布：落地先看、休息、日总量、读写配比；对数正态时序 + 相邻相关；间隔序列进观测；哨兵去痕迹；契约层可注入测试 | 81 条单测，门禁 11 条断言 | 阈值未经真人样本校准；真站未复测 |
| 8 | 下一级 | 自迭代收敛：改动→判定→留下或回退，无需人介入 | 迭代台账里连续多代 `kept` 且分项不退化 | — |

> **case：第三次拦截怎么变成了第二级**
> 三次拦截里最隐蔽的一次是「3 分钟 5 轮搜索、10 次动作、0 次开详情」。
> 总量不大、节奏也不快，但结构上是一个只会搜索不会阅读的机器。
> 现在的对策是 `search_no_detail` 与 `chain_repeat` 两个评分项，加上 30 分钟内无响应第二次即熔断。
> 它不是「加了个延迟」，而是把「只搜不开」本身当成可疑结构。

## 七、自迭代

迭代让系统自己变好，但有一道红线：**只能迭代数据，不能迭代判定标准。**

| 层 | 内容 | 谁能改 |
| --- | --- | --- |
| 可变 | 站点参数覆盖、配方步骤、经验条目 | agent |
| 冻结 | 判定阈值、禁写边界、写动作分类、冷却下限 | 只有人 |

理由很直接：让 agent 改门禁，等于让它自己发合格证。

**一次改动一行。** `iterations` 表记录：改了什么（`before` / `after`）、为什么（`rationale`）、
依据哪条证据（`evidence`）、门禁前后（`gate_before` / `gate_after`）、结果（`kept` / `reverted`）。
`generation` 按 (站点, 意图) 递增，用来聚合「第几代」。

**判定与退回。** 改动后必须过一次门禁：

- L1 任一断言失败 → 立即回退；
- L2 任一分项退化超过 5% → 回退；
- 同一 (站点, 意图) 连续 3 代没有改善 → 停手，升级为告警等人工裁决。

没有停止条件的自迭代会变成无限调参，最后把参数推到「刚好不报警」的位置——比不做还差。

```bash
node tools/iterate.mjs record --site liepin.com --intent search --kind param \
  --before '{"budget.search.gap":[45000,120000]}' \
  --after  '{"budget.search.gap":[60000,150000]}' \
  --rationale "搜索间隔偏紧，先放宽" --trigger budget
node tools/iterate.mjs list --site liepin.com
node tools/iterate.mjs decide --id 1 --outcome kept --reason "门禁 6/6，分项无退化"
```

## 八、边界与不做

**不做**：不伪造指纹（真机真 GPU 真登录态已经一致，改反而制造矛盾）、
不绕验证码（遇到挑战停手、留证据、通知你、把控制权交出去）、不轮换账号（那是绕过封禁，不是拟人）。

**已知限制**，每条都写清卡在哪：

1. **收藏与投递未验证**：结果卡片是 `div` 不是 `a`，点击目标未定准。缺的不是机制，是一个可靠的定位符。
2. **`role:` 定位依赖文本匹配**：复杂 aria 结构下会失败。失败即抛，不降级——这是有意的。
3. **HTTP 403/429 的响应头级检测未实现**：读响应头要开 `Network` 域，而 `page.events()` 会清空 ego 的事件缓冲，可能干扰弹窗与下载等待。
4. **并发跑多个脚本**：跨进程配额与冷却会互相覆盖；配额应按站点聚合，目前按行累加。
5. **`silentWrite` 会被前端框架的受控输入误伤**：权重已压低，仅作诊断。
6. **停手通知依赖一次性授权**：站点要允许通知、系统要允许 Chrome 通知，换机器或清了权限都要重来；
   没授权时只剩 `alerts` 表可查，「及时触达」就退化成「回来以后翻记录」。

## 九、快速开始

```bash
# 装成 skill（Windows 用 junction，改动即时生效）
powershell -ExecutionPolicy Bypass -File .\install.ps1
./install.sh              # macOS / Linux
```

```js
const task = await taskSpace("liepin 候选人筛选");
const page = task.page("p1");
await page.goto("https://www.liepin.com/");

const h = await human.create(page);
console.log(h.site());            // { host, siteKey, profile }
console.log(h.health.warnings);   // 体检告警，空数组为正常

await h.click("role:link[name='找人']");
await h.read();                   // 5–8 秒停顿 + 1–2 次滚轮
await h.type("供应链总监");
await h.press("Enter");
await h.click("role:button[name='搜 索']", { as: "search" });
await h.flush();
```

```bash
node tools/lint-script.mjs examples/liepin-search.mjs   # 跑前扫一遍写路径
node tools/verify-human.mjs                              # 跑后过一遍门禁
```
